# Customer Support AI Agent Reflection

The most important design decision in this project was to keep customer-support capabilities as specialized, grounded tools instead of relying on the language model to remember or calculate everything. The AgentCore Gateway supplies current order and refund operations, the managed Knowledge Base supplies catalog and policy information, AgentCore Memory supplies conversational facts and preferences, Code Interpreter performs loyalty arithmetic, and Browser handles public live-web questions. I used a stable customer ID together with separate session IDs so that the agent could recall a customer preference across sessions without treating memory as an authority for current orders or financial information. This separation reduces hallucination risk: current operational data comes from tools, while memory provides only context.

A real challenge was deploying direct code from Windows to AgentCore's Linux ARM64 Runtime. The legacy Starter Toolkit initially could not find the required zip utility, then its Windows dependency resolution included platform-specific packages that could not be installed into the Linux deployment ZIP. I installed the genuine zip utility, produced a deployment requirements file that retained the Windows-only marker, and verified the Linux ARM64 dependency target before redeploying. I also encountered an OpenTelemetry entrypoint mismatch caused by the Toolkit detecting an instrumentation library without its executable; disabling that optional instrumentation produced a valid Runtime entrypoint. The deployed tests then validated order tracking, refund processing, RAG, cross-session memory, Code Interpreter loyalty calculations, and live Browser retrieval.

For production, I would replace the educational Gateway's unauthenticated inbound setting with authenticated access, keep the runtime role least-privilege, store configuration and secrets outside source code, and apply encryption, retention limits, and consent controls to customer memory. I would add confirmation steps before real refunds, structured audit logs, monitoring and alerting, rate limits, automated integration tests, and private network connectivity where appropriate.
